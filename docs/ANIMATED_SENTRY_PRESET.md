# Анимированные турели из Workshop для CS2Turrets (экспериментально)

## Проверенная точка входа

- Открытый плагин [HanTurretS2](https://github.com/H-AN/HanTurretS2) указывает ресурс Steam Workshop ID **3618032051** и приводит пути Source 2 моделей.
- Это **кандидат на анимированную турель**, но **не доказанная модель M134 Minigun с вращающимся блоком стволов**. Название клипа `fire` в конфиге есть; действительно ли в нём крутятся стволы, надо просмотреть в Source2Viewer и проверить в игре.
- Исходный проект использует **Swiftly2**, а данный репозиторий — **CounterStrikeSharp**. Исходники Swiftly не переносились: здесь только опциональный вызов Source 2 entity input `SetAnimationNoReset` для уже доступного ресурса.
- **Сами модели, текстуры, звук и Workshop-аддон не входят в репозиторий, DLL или серверный ZIP**; права на распространение сохраняются за авторами.

## Подключение ресурса на тестовом сервере

1. Установить совместимый с текущей версией CS2 MultiAddonManager и его зависимости.
2. В `game/csgo/cfg/multiaddonmanager/multiaddonmanager.cfg` добавить Workshop ID `3618032051` в `mm_extra_addons`. Синтаксис конфигурации зависит от версии MultiAddonManager; не заменять существующие ID.
3. Убедиться, что сервер и клиент получили аддон. С помощью Source2Viewer открыть фактически загруженный VPK и **подтвердить** существование нужных `.vmdl_c`, `fire` и `idle` (если доступна) анимаций, путь `muzzle` и наличие вращения стволов.
4. В `addons/counterstrikesharp/configs/plugins/CS2Turrets/CS2Turrets.json` включить экспериментальный профиль, **меняя только указанные поля**:

```json
{
  "UseCustomTurretModel": true,
  "UseTeamSkins": true,
  "TerroristStandardModel": "models/stk_sentry_guns/sentry/lvl_3_t.vmdl",
  "CounterTerroristStandardModel": "models/stk_sentry_guns/sentry/lvl_3_ct.vmdl",
  "TerroristRocketModel": "models/stk_sentry_guns/sentry/lvl_4_t.vmdl",
  "CounterTerroristRocketModel": "models/stk_sentry_guns/sentry/lvl_4_ct.vmdl",
  "CustomFireAnimation": "fire",
  "CustomIdleAnimation": ""
}
```

5. Если у модели есть подходящий клип `idle`, можно установить `"CustomIdleAnimation": "idle"`, чтобы переводить анимацию в состояние покоя после потери цели. **Не придумывать** название: предварительно проверить в просмотрщике.
6. Перезапустить сервер, сменить карту, проверить оба цвета, стрельбу и E-улучшение. Перед использованием на публичном сервере проверить рендер, сетевую доставку, FPS, трассировку и `killfeed`.

### Что это меняет

- При **первом выстреле в очереди** плагин один раз посылает `SetAnimationNoReset("fire")` всем визуальным моделям турели. Повторные выстрелы не сбрасывают непрерывную анимацию.
- При потере цели посылается `SetAnimation("idle")` **только если задан `CustomIdleAnimation`**.
- Если `fire` нецикличен, вращение может прекратиться до конца очереди. Для постоянного вращения нужен **циклический клип** в `.vmdl_c` либо отдельная анимированная часть/кость, поддерживаемая Source 2.
- На **4 уровне** текущая логика плагина всё ещё запускает ракеты. Изображение ракетного узла в Workshop-модели нужно проверять отдельно — найденные модели не гарантируют наличие внешнего ракетного блока.
- Если оставлен `CustomProjectileModel = models/cs2turrets/rocket.vmdl`, отдельная модель ракеты по-прежнему обязательна. Без неё будут ошибки отсутствующего ресурса. Для полностью рабочего 4 уровня необходимо подготовить собственную ракету или адаптировать визуальный fallback.

Это **исследовательский прототип**, не «готовый миниган». CS2 серверный runtime не запускался, видеоподтверждения вращения найденного аддона нет.
